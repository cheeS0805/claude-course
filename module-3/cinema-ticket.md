# Міні-проєкт модуля 3. Квиток у кіно

**Мета:** зібрати все з модуля 3 в одну програму — порівняння, умови з назвами, ланцюжок з охоронними умовами і таблицю випадків з перевіркою на кожен рядок.

## Правила кінотеатру «Зоря»

1. Сеанси починаються щогодини з 9:00 до 23:00. Час сеансу — ціле число від 9 до 23. Інший час — «Такого сеансу немає».
2. Вік — від 0 до 120 років. Інший — «Перевірте вік».
3. Нічні сеанси (з 22:00) — лише з 18 років. Інакше — «Нічний сеанс — лише з 18 років».
4. Денний сеанс (до 18:00) коштує 140 грн, вечірній і нічний (з 18:00) — 180 грн.
5. Діти до 6 років — безкоштовно.
6. Діти від 6 до 17 років і студенти зі студентським — на 40 грн дешевше.
7. Пенсіонери від 65 років на денні сеанси — 70 грн.
8. Знижки не додаються: якщо людині підходить кілька, діє та, з якою квиток дешевший.
9. Середа — день кіно: кожен платний квиток дешевший на 30 грн. Це не знижка з правила 8: вона рахується після всіх інших.

## 1. Питання і варіанти

| Питання | Варіанти |
|---|---|
| Вік | 0–5 (безкоштовно) · 6–17 (дитячий) · 18–64 (дорослий) · 65–120 (пенсіонер) |
| Студентський? | так / ні |
| Середа? | так / ні |
| Година | денний 9–17 · вечірній 18–21 · нічний 22–23 |

Повна таблиця без неправильних даних: 4 × 2 × 2 × 3 = **48 рядків**.

Комбінації, що не мають сенсу або дають однакову відповідь:
- студентський для дитини до 6 років — вона й так безкоштовно;
- студентський для дитини 6–17 років — знижка та сама (−40), знижки не додаються;
- нічний сеанс для молодших 18 — відмова за будь-якого дня і студентського;
- пенсіонер увечері — правило 7 не діє, рахується як дорослий.

Тому замість 48 рядків — рядки, що покривають кожне правило і кожну межу з обох боків (граничні значення: межа − 1, межа, межа, межа + 1).

## 3. Порядок перевірок

1. **Охоронні умови першими:** година → вік → нічний сеанс для молодших 18. Неправильні дані не отримують ціни.
2. **Базова ціна:** денний — 140, вечірній і нічний — 180.
3. **Знижки:** дитина до 6 — 0. Інакше: студентська знижка −40, а потім 70 грн для пенсіонера вдень — лише якщо так дешевше. Програма порівнює ціни, тому виконується правило 8: знижки не додаються, діє найвигідніша.
4. **Середа — в самому кінці**, окремо від ланцюжка знижок: за правилом 9 вона рахується після всіх інших і лише для платних квитків.

## 4. Код (перевірка всієї таблиці)

Запускається в консолі браузера (F12 → Console).

```js
// ---- тарифи і правила кінотеатру ----
const FIRST_HOUR = 9;
const LAST_HOUR = 23;
const EVENING_FROM = 18;
const NIGHT_FROM = 22;
const MIN_AGE = 0;
const MAX_AGE = 120;
const ADULT_AGE = 18;
const FREE_UNDER = 6;
const CHILD_TO = 17;
const SENIOR_FROM = 65;
const DAY_PRICE = 140;
const EVENING_PRICE = 180;
const STUDENT_DISCOUNT = 40;
const SENIOR_DAY_PRICE = 70;
const WEDNESDAY_DISCOUNT = 30;
const MOVIE_DAY = "ср";

// ---- таблиця перевірок: [вік, студентський?, день, година, очікували] ----
const cases = [
  [30, false, "пн", 12, "Ціна квитка: 140 грн"],
  [30, false, "пн", 19, "Ціна квитка: 180 грн"],
  [0, false, "пн", 12, "Ціна квитка: 0 грн"],
  [5, false, "пн", 12, "Ціна квитка: 0 грн"],
  [6, false, "пн", 12, "Ціна квитка: 100 грн"],
  [17, false, "пн", 19, "Ціна квитка: 140 грн"],
  [18, false, "пн", 19, "Ціна квитка: 180 грн"],
  [30, true, "пн", 12, "Ціна квитка: 100 грн"],
  [64, false, "пн", 12, "Ціна квитка: 140 грн"],
  [65, false, "пн", 12, "Ціна квитка: 70 грн"],
  [65, false, "пн", 19, "Ціна квитка: 180 грн"],
  [65, true, "пн", 12, "Ціна квитка: 70 грн"],
  [65, true, "пн", 19, "Ціна квитка: 140 грн"],
  [120, false, "пн", 12, "Ціна квитка: 70 грн"],
  [30, false, "ср", 12, "Ціна квитка: 110 грн"],
  [65, false, "ср", 12, "Ціна квитка: 40 грн"],
  [4, false, "ср", 12, "Ціна квитка: 0 грн"],
  [30, false, "пн", 8, "Такого сеансу немає"],
  [30, false, "пн", 9, "Ціна квитка: 140 грн"],
  [30, false, "пн", 17, "Ціна квитка: 140 грн"],
  [30, false, "пн", 18, "Ціна квитка: 180 грн"],
  [17, false, "пн", 21, "Ціна квитка: 140 грн"],
  [17, false, "пн", 22, "Нічний сеанс — лише з 18 років"],
  [18, false, "пн", 22, "Ціна квитка: 180 грн"],
  [30, false, "пн", 23, "Ціна квитка: 180 грн"],
  [30, false, "пн", 24, "Такого сеансу немає"],
  [-1, false, "пн", 12, "Перевірте вік"],
  [121, false, "пн", 12, "Перевірте вік"],
];

for (const [age, isStudent, day, hour, expected] of cases) {
  // ---- умови з назвами ----
  const isValidHour = Number.isInteger(hour) && hour >= FIRST_HOUR && hour <= LAST_HOUR;
  const isValidAge = age >= MIN_AGE && age <= MAX_AGE;
  const isNight = hour >= NIGHT_FROM;
  const isEvening = hour >= EVENING_FROM;
  const isFreeChild = age < FREE_UNDER;
  const hasStudentDiscount = (age >= FREE_UNDER && age <= CHILD_TO) || isStudent;
  const isSeniorDay = age >= SENIOR_FROM && !isEvening;
  const isMovieDay = day === MOVIE_DAY;

  // ---- охоронні умови першими ----
  let message = "";
  if (!isValidHour) {
    message = "Такого сеансу немає";
  } else if (!isValidAge) {
    message = "Перевірте вік";
  } else if (isNight && age < ADULT_AGE) {
    message = "Нічний сеанс — лише з 18 років";
  } else {
    // ---- правила ціни ----
    let price = DAY_PRICE;
    if (isEvening) {
      price = EVENING_PRICE;
    }
    if (isFreeChild) {
      price = 0;
    } else {
      if (hasStudentDiscount) {
        price = price - STUDENT_DISCOUNT;
      }
      // знижки не додаються: 70 для пенсіонера — лише якщо так дешевше
      if (isSeniorDay && SENIOR_DAY_PRICE < price) {
        price = SENIOR_DAY_PRICE;
      }
    }
    // середа — після всіх знижок і лише для платних
    if (isMovieDay && price > 0) {
      price = price - WEDNESDAY_DISCOUNT;
    }
    message = `Ціна квитка: ${price} грн`;
  }

  // ---- перевірка ----
  if (message === expected) {
    console.log(age, isStudent, day, hour, "→", message, "OK");
  } else {
    console.log(age, isStudent, day, hour, "→", message, `ПОМИЛКА: очікували «${expected}»`);
  }
}
```

- В умовах немає «голих» цін і годин — лише константи.
- Ціна — число, а відмова — текст, тому відповідь спершу складається в одну змінну `message`, і з `expected` порівнюється саме вона.
- `Number.isInteger(hour)` перевіряє, що година — ціле число: сеанси лише щогодини.

Три запуски (вік 30, година 12):

| Ввід | Вивід | Мало бути |
|---|---|---|
| так, ср | Ціна квитка: 70 грн | 70 (140 − 40 − 30) ✅ |
| **Так**, ср | Ціна квитка: 110 грн | 70 — студентська знижка зникла ❌ |
| так, **середа** | Ціна квитка: 100 грн | 70 — день кіно не спрацював ❌ |

**Чому людина не дізналась про помилку:** `"Так" === "так"` і `"середа" === "ср"` — неправда, бо порівнюються рядки буква в букву. Програма не падає і не попереджає, а мовчки вирішує «студентського немає» або «не середа» і видає ціну, яка виглядає цілком нормальною. Захист на майбутнє: приводити ввід до одного вигляду (`toLowerCase()`) і перевіряти, що відповідь — саме «так» / «ні», а день — один із семи; інакше — «Перевірте день».

## 6. Правила окремо від коду

| Частина | Знає | Вміє | Говорить з |
|---|---|---|---|
| Ввід | які чотири питання поставити | спитати людину, перетворити відповіді (`Number`, `=== "так"`) | передає дані Перевірці |
| Перевірка даних | допустимі години й вік | відсіяти неправильне: «Такого сеансу немає», «Перевірте вік», «Нічний сеанс — лише з 18 років» | бере межі з Тарифів; пропускає дані до Правил ціни або передає відмову у Вивід |
| Тарифи (константи) | усі числа правил: ціни, знижки, години, вікові межі | лише зберігає | ними користуються Перевірка і Правила ціни |
| Правила ціни | порядок: база → найвигідніша знижка → середа | порахувати ціну | бере Тарифи, передає ціну у Вивід |
| Вивід | формат «Ціна квитка: … грн» | показати відповідь | показує людині |

**А. Telegram-бот з тими самими цінами.** Без змін переходять Тарифи, Перевірка даних і Правила ціни. Заново пишуться Ввід (питання приходять повідомленнями) і Вивід (відповідь надсилається в чат).

**Б. Денний квиток дешевшає до 100 грн.** Змінюється одна константа: `DAY_PRICE = 100`. Пенсіонер зі студентським на денний сеанс: студентський — 100 − 40 = 60, пенсійний — 70; за правилом 8 діє дешевший — **60 грн**. Програма відповідає 60, бо порівнює ціни (`SENIOR_DAY_PRICE < price`), а не вважає наперед, що пенсійний квиток найдешевший. Якби пенсіонера перевіряли першим ланцюжком `else if` («пенсіонер — 70, і стоп»), у порядок перевірок було б непомітно «зашите» припущення «70 завжди дешевше за студентський». При 140 це правда (70 < 100), а при 100 — ні (70 > 60): правило 8 мовчки зламалося б.

**В. «Кіноклуб»: власник картки має знижку 20% у будь-який день.**
- Таблиця: нове питання «є картка клубу?» і нові рядки — особливо разом зі студентським, пенсіонером і середою.
- Порядок: 20% — ще одна знижка, що бере участь у виборі найвигіднішої (правило 8); середа лишається в кінці.
- Код: у Вводі — нове питання, у Тарифах — константа `CLUB_DISCOUNT_PERCENT = 20`, у Правилах ціни — ще одне порівняння «чи так дешевше».
- Не змінюються: Перевірка даних і Вивід.
- Неоднозначне місце — питання до директора: «Від якої ціни рахувати 20% — від базової чи від уже зниженої? Ця знижка конкурує з іншими (діє найвигідніша) чи додається до них? І чи додається до неї середа?»

**Одним реченням:** правила — це константи-тарифи і таблиця перевірок (скільки, від якого віку, о котрій), а код — ланцюжок умов, який лише бере ці числа і застосовує їх у правильному порядку.
